# coap_spark comparison benchmark

This benchmark compares AdaLang Analyzer's `--verify` bounded-scalar proof
obligations against GNATprove's `--mode=prove` results, per obligation (same
file, line, and check kind), on a pinned revision of
[mgrojo/coap_spark](https://github.com/mgrojo/coap_spark) (Apache-2.0 OR
GPL-2.0-or-later, actively maintained by Manuel Gomez) — a client/server
implementation of the Constrained Application Protocol (CoAP, RFC 7252) in
SPARK, with its message parsers and encoders generated by
[AdaCore/RecordFlux](https://github.com/AdaCore/RecordFlux) from a formal
protocol specification.

This is a fifth, independently authored corpus (Manuel Gomez/mgrojo, distinct
from SPARKNaCl's rod-chapman, Saatana's HeisenbugLtd, CubedOS's cubesatlab,
and libkeccak's damaki) in a domain none of the other four touch: network
protocol message parsing and a client/server session state machine, rather
than a cryptographic primitive or hash family. Most of its proof obligations
come from RecordFlux-generated field encoders/decoders and the hand-written
session and channel logic built on top of them, not hand-written arithmetic.

## A candidate rejected first: HiRTOS

[jgrivera67/HiRTOS](https://github.com/jgrivera67/HiRTOS), a SPARK
multi-core RTOS kernel, was considered before this corpus specifically to
diversify into a concurrency/systems domain. It was set aside: GNATprove
hard-errors (not just leaves things unproved) on this benchmark suite's
toolchain, reproducibly from a clean build --

```
hirtos-interrupt_handling.ads:13: error: function "Enter_Interrupt_Context"
  with output global "HiRTOS_Obj" is not allowed in SPARK [E0005]
```

-- a genuine SPARK legality violation (a function with a side-effecting
output global) in the interrupt-handling code itself, not an environment
mismatch. HiRTOS's last commit predates this repository's GNATprove pin by
roughly two years and carries no CI running GNATprove at all, so this was
never caught upstream. Not pursued further.

## Toolchain override: SPARKlib version conflict

coap_spark's own root `sparklib.gpr` is a thin wrapper: `project SPARKlib
extends "sparklib_external"`, a project name that only resolves inside
Alire's per-crate release layout for the `gnatprove` dependency coap_spark's
own `alire.toml` pins (`gnatprove = "^14.1.1"`, matched to the GNAT
Community 2021 "Colibri" toolchain upstream's own CI uses — see
`.github/workflows/prove.yml`). This benchmark suite's GNATprove is FSF
16.1.0 (the same pin `benchmarks/libkeccak/RESULTS_*.md` and the other three
benchmarks' results document), which bundles its own SPARKlib. Loading both
at once — coap_spark's explicit `with "sparklib.gpr"` chain resolving to the
14.1.1-era copy, plus 16.1.0's own implicit copy — produces `"Append" must
denote exactly one subprogram` ambiguity errors, and GNATprove aborts before
analyzing anything (confirmed reproducibly from a clean `obj/`).

Rather than run this one benchmark on a GNATprove version inconsistent with
the other four, `run.sh` points `GPR_PROJECT_PATH` at Alire's own `sparklib`
crate, release **16.1.0** — built explicitly "for use with GNATprove FSF
16" per its own crate description — deployed standalone, *outside*
coap_spark's own Alire workspace, ahead of `coap_spark_root` itself. Because
both projects are literally named `SPARKlib`, `with "sparklib.gpr";` in
coap_spark.gpr then resolves to the 16.1.0-compatible copy instead of the
repository's own wrapper, with no source edits to the pinned checkout.
`-XSPARKLIB_INSTALLED=False` switches that crate's own source-root
computation from "installed inside a GNAT toolchain layout" (which it is
not, deployed standalone) to its bundled `src/` directory. With this in
place, the same SPARK legality/version-conflict category of failure that
ruled out HiRTOS does not occur here: zero legality errors, in every run.

`coap_spark.gpr`'s own `Prove` package also names `colibri` (AdaCore's
proprietary prover, not part of this toolchain's Z3/CVC5/Alt-Ergo bundle)
and carries no `--report` switch, the same gap `benchmarks/saatana/`'s own
Prove package has — GNATprove's default of reporting only failed checks in
`--output=oneline` mode leaves almost nothing for `compare.awk` to match
against AdaLang's obligations (confirmed interactively: 42 messages total
without `--report=statistics`, 7,858 with it, for the identical run).
`run.sh` overrides `--prover=z3,cvc5,altergo` (replacing the project's list
outright, which drops `colibri`) and adds `--report=statistics`, matching
SPARKNaCl's and Saatana's own benchmark invocations.

## Scope: coap_spark.gpr, the library itself

This benchmark targets `coap_spark.gpr` directly — the shared protocol
library (85 files: RecordFlux-generated message parsers/encoders under
`generated/` and `src/`, plus the hand-written session, channel, and
resource logic) — the same convention `benchmarks/libkeccak/`,
`benchmarks/saatana/`, and `benchmarks/sparknacl/` use of proving the
library rather than a driver. `client/coap_client.gpr` and
`server/coap_server.gpr` (thin CLI/session drivers on top of the same
library) were not used as the benchmark's project scope: AdaLang Analyzer's
`-P<project>.gpr` analyzes that project's own declared `Source_Dirs` only,
not transitively-`with`ed library projects, so pointing it at
`coap_client.gpr` directly analyzed only the 4 files under `client/src/`
and missed the library entirely — a scope bug caught by comparing analyzed-
file counts across lanes before finalizing this benchmark, not an AdaLang
defect (GNATprove's `--mode=prove`, by contrast, always analyzes the full
project closure regardless of which `.gpr` it is pointed at). An earlier,
uncorrected run also showed the client- and library-scoped runs disagreeing
(14 vs. 138 medium findings) because the first library-scoped GNATprove
invocation omitted `-f` and picked up a stale partial-verification cache;
forcing a clean re-verification (`-f`, which `run.sh` always passes) shows
both scopes agree exactly. `run.sh` targets `coap_spark.gpr` alone.

## Pinned sources

- mgrojo/coap_spark: `2fa345b8c70d621287b932aee7ea39b3520a5adf`
- wolfssl submodule (`libs/wolfssl`): `59f4fa568615396fbf381b073b220d1e8d61e4c2`

Clone the corpus from the AdaLang Analyzer repository root. The
`tools/RecordFlux` submodule is codegen tooling only — the RecordFlux-
generated sources are already checked into `generated/` and `src/`, so it is
not needed to build or prove this corpus and is skipped below.

```sh
git clone https://github.com/mgrojo/coap_spark.git \
  /private/tmp/adalang-coap-spark-benchmark
git -C /private/tmp/adalang-coap-spark-benchmark checkout \
  2fa345b8c70d621287b932aee7ea39b3520a5adf
git -C /private/tmp/adalang-coap-spark-benchmark submodule update --init \
  -- libs/wolfssl
```

coap_spark is Alire-native: `coap_spark.gpr` `with`s
`config/coap_spark_config.gpr`, generated by Alire and not checked into the
repository. `--stop-after=generation` runs only Alire's own config-file
generation, not a full build — this corpus's wolfssl C sources do not
compile cleanly against this benchmark suite's Clang/macOS SDK combination
(a pre-existing upstream C portability issue, unrelated to the Ada/SPARK
code this benchmark analyzes), so a full `alr build` is neither needed nor
attempted:

```sh
cd /private/tmp/adalang-coap-spark-benchmark && alr build --stop-after=generation
```

This also deploys Alire's own `gnatprove=14.1.1` and its matched `sparklib`
release into the Alire workspace as declared dependencies — harmless (unused
by `run.sh`, which never invokes `alr gnatprove` and points at this
benchmark suite's own FSF 16.1.0 `gnatprove` instead) but expect the
one-time toolchain download.

Deploy the FSF-16.1.0-compatible SPARKlib crate standalone (see "Toolchain
override" above) — `alr get` deploys under the current directory, into a
`sparklib_<version>_<hash>/` folder it names itself:

```sh
mkdir -p /private/tmp/adalang-coap-spark-sparklib
cd /private/tmp/adalang-coap-spark-sparklib && alr get sparklib=16.1.0
```

Run the benchmark:

```sh
COAP_SPARK_ROOT=/private/tmp/adalang-coap-spark-benchmark \
COAP_SPARK_SPARKLIB=/private/tmp/adalang-coap-spark-sparklib/sparklib_16.1.0_6d13c714 \
  sh benchmarks/coap_spark/run.sh
```

(The exact `sparklib_16.1.0_*` directory name includes a content hash that
may differ; check what `alr get` actually named it under
`adalang-coap-spark-sparklib/`.)

`run.sh` verifies both pinned revisions, then runs:

- AdaLang `--verify` against `coap_spark.gpr`, `--format=json`;
- GNATprove `--mode=prove --output=oneline` against the same project, with
  the toolchain overrides described above;
- `compare.awk` (identical to the other four benchmarks' copies) over both
  outputs, writing `comparison.txt` to the results directory (default
  `benchmark-results/coap_spark/`, override with `RESULTS_DIR`).

## Matching design

Same as `benchmarks/sparknacl/`, `benchmarks/saatana/`,
`benchmarks/cubedos/`, and `benchmarks/libkeccak/`: obligations are matched
by `(basename(file), line, normalized check kind)`, count-mismatched
locations are reported separately rather than guessed, and `compare.awk`'s
five per-pair buckets and two coverage-only counts have the same meaning.
See `benchmarks/sparknacl/README.md` for the full design description.

One nuance specific to this corpus: AdaLang's `Unreachable` proof status
(dead-code paths it determines cannot execute) is a distinct status from
`Unproved`/`Definite_Error`, but `compare.awk`'s bucket taxonomy has no
dedicated bucket for "AdaLang says unreachable, GNATprove proves the check
trivially true anyway" — it is not a disagreement about safety, just two
compatible classifications the script does not distinguish, and it falls
into the generic Bucket 5 ("both flag a problem") catch-all rather than
somewhere more precise. See the latest `RESULTS_*.md` for how many of that
run's Bucket 5 entries are this benign mismatch versus a genuine agreement.

## Caveats

- GNATprove version, solver versions, and exact message wording are recorded
  in each dated `RESULTS_*.md` for reproducibility.
- This corpus is not claimed fully proved by its own upstream CI even on its
  intended toolchain (GNAT Community 2021 + colibri); this benchmark's own
  run at this toolchain's much shorter `--timeout=60` budget (vs. the
  project's own `--timeout=360`) leaves a small number of medium residuals,
  documented per-run in `RESULTS_*.md`.
- The GNATprove message-text substring matching in `compare.awk` is a
  heuristic against observed wording, not a stable GNATprove API — see
  `benchmarks/sparknacl/README.md`'s caveat for the same point.

See the latest `RESULTS_*.md` in this directory for recorded runs.
