## Environment and scope

- mgrojo/coap_spark: `2fa345b8c70d621287b932aee7ea39b3520a5adf`
- wolfssl submodule (`libs/wolfssl`): `59f4fa568615396fbf381b073b220d1e8d61e4c2`
- AdaLang Analyzer: `1.0.0-rc1`, commit `d9666a3bf55a18f545d6b9b04f35f5cc3d413175`
- GNATprove: FSF 16.1.0, Why3 1.8.2+git, CVC5 1.3.2, Z3 4.15.4, Alt-Ergo 2.6.1
- SPARKlib: Alire crate `sparklib=16.1.0` (deployed standalone, substituted for
  coap_spark's own `gnatprove=14.1.1`-matched copy — see
  `benchmarks/coap_spark/README.md`, "Toolchain override")
- Compiler: Alire `gnat_native` toolchain (this repository's own pin)
- Host: Apple Silicon, macOS 26.5.2
- Project: `coap_spark.gpr -XSPARKLIB_INSTALLED=False`, 85 source files under
  `generated/` (RecordFlux-generated message parsers/encoders) and `src/`
  (session, channel, and resource logic), analyzed by both tools
- GNATprove ran with `-P coap_spark.gpr -XSPARKLIB_INSTALLED=False
  --mode=prove -f -q --output=oneline --prover=z3,cvc5,altergo --steps=16000
  --timeout=60 --report=statistics` — three overrides of coap_spark's own
  `Prove` package (`colibri` dropped from `--prover`, since it is AdaCore's
  proprietary prover and not part of this toolchain's bundle; `--steps=0
  --timeout=360` narrowed to `--steps=16000 --timeout=60`, the same budget
  `benchmarks/libkeccak/`'s own Prove package uses; `--report=statistics`
  added, since the project's own Prove package has none — see
  `benchmarks/coap_spark/README.md`, "Toolchain override", for why each was
  necessary)

**coap_spark is essentially fully proved at this configuration.** GNATprove's
own summary (`benchmark-results/coap_spark/gnatprove.out`) reports 7,526
total checks, 14 unproved (0%), 0 justified. All 14 residuals are "provers
reached time and step limit" — a resource-budget shortfall on this
toolchain's `--timeout=60` (a sixth of the project's own `--timeout=360`),
not a demonstrated defect — concentrated in two spots: seven
`RFLX_Types.Fits_Into` preconditions in RecordFlux-generated field encoders
(one per generated protocol module: `CoAP`, `CoAP_Client`, `CoAP_Server`, and
their `Option_Type`/`Definite_Message`/`Application_Response`/
`Options_And_Payload_Data` submodules), and seven overflow/postcondition
checks in `rflx_rflx_arithmetic` (a small generic bit-width arithmetic
helper both RecordFlux-generated modules share). Both scopes checked before
settling on this one (`coap_spark.gpr` alone and, via
`client/coap_client.gpr`, the library plus its CLI driver) show the
identical 14 residuals once GNATprove is forced to re-verify cleanly (`-f`)
— see `benchmarks/coap_spark/README.md`, "Scope", for the caching artifact
that initially made them look different.

## A candidate rejected first: HiRTOS

[jgrivera67/HiRTOS](https://github.com/jgrivera67/HiRTOS) was investigated
first to diversify this repository's benchmark corpus into a
concurrency/systems domain. GNATprove hard-errors on it reproducibly, from a
clean build, on this toolchain: `hirtos-interrupt_handling.ads:13: error:
function "Enter_Interrupt_Context" with output global "HiRTOS_Obj" is not
allowed in SPARK [E0005]` — a genuine SPARK legality violation (a function
with a side-effecting output global), not an environment mismatch. Its last
commit predates this repository's GNATprove pin by roughly two years, with
no CI running GNATprove at all. Set aside; not pursued further. See
`benchmarks/coap_spark/README.md` for the full account.

## Agreement: matched obligations

Matched by `(file, line, check kind)` — see `benchmarks/coap_spark/README.md`
and `benchmarks/sparknacl/README.md` for the matching design. **846**
obligations matched 1:1:

| Bucket | Count | Meaning |
| --- | ---: | --- |
| Both safe | 1 | AdaLang `Proved_Safe`, GNATprove proved |
| AdaLang conservative | 835 | AdaLang `Unproved`/`Unsupported`, GNATprove proved |
| **Possible AdaLang unsoundness** | **0** | AdaLang `Proved_Safe`, GNATprove NOT proved |
| **AdaLang false positive** | **0** | AdaLang `Definite_Error`, GNATprove proved |
| Both flag a problem | 10 | Both non-safe |

Zero obligations in either headline-risk bucket, consistent with SPARKNaCl,
Saatana, and libkeccak: AdaLang never called something safe that GNATprove
could not prove, and never called something a definite error that GNATprove
proved safe, anywhere in the matched set — on a fifth independent corpus, in
a domain (protocol message parsing and session state) none of the other four
touch.

### Bucket 5 ("both flag a problem") is mostly a labeling nuance, not disagreement

9 of the 10 Bucket 5 entries are AdaLang marking a check `Unreachable`
(dead-code paths it determines cannot execute) while GNATprove separately
proves the same, unreachable check trivially true — two compatible
classifications `compare.awk`'s five-bucket taxonomy has no dedicated slot
for, not a safety disagreement; see `benchmarks/coap_spark/README.md`,
"Matching design", for why this falls into the catch-all bucket. The 10th
entry is a genuine agreement: both tools independently flag uncertainty at
`rflx_rflx_arithmetic.adb:79` (an assertion GNATprove could not discharge
within budget — the same location as one of the 14 unproved checks above).

### Why the matched-pair count is small relative to the obligation totals

Similar to libkeccak (212 matched out of 11,202), coap_spark's matched-pair
count (846 out of 11,949) is small in *proportion* because of **813**
count-mismatch keys, the second-largest such bucket after libkeccak's. The
cause here is not libkeccak's generic-instantiation-per-state-size pattern
but RecordFlux's own code-generation style: `precondition` dominates the
mismatch bucket (most entries show `adalang=2 gnatprove=1`), because
RecordFlux generates two related precondition checks per field-access
call — one for the containing message context, one for the field itself —
that GNATprove reports as a single combined check message at that call site
while AdaLang, analyzing each contract individually, reports two obligations.
As with libkeccak, `compare.awk`'s policy is to report a count mismatch for
manual review rather than guess which obligation corresponds to which
message; this is a property of RecordFlux's generated-contract structure,
not a matching defect.

## Coverage-only counts

- **6,039** AdaLang obligations have no GNATprove `--mode=prove` counterpart
  for that kind at any matched location — dominated by `initialization-check`
  (4,066), the same category that dominates SPARKNaCl's and libkeccak's
  coverage-only counts, for the same reason: GNATprove tracks initialization
  primarily as a flow fact rather than a per-obligation "proved" check
  message in `--output=oneline`.
- **2,274** GNATprove-only obligations (a mapped kind, but no AdaLang
  obligation recorded at that exact location) — `precondition` (1,273) and
  `range-check` (444) dominate, the mirror image of the count-mismatch
  bucket above: RecordFlux's paired-precondition generation pattern produces
  GNATprove messages at locations where AdaLang's per-contract analysis
  attributes the corresponding obligation to a different but nearby line.
- **2,528** GNATprove messages have no AdaLang kind mapping at all —
  overwhelmingly flow and termination facts (`implicit aspect
  Always_Terminates on "<entity>" has been proved`, `initialization of
  "<var>" proved`, container-library discriminant/quantification checks from
  SPARKlib's own formal containers) that `--verify`'s obligation model does
  not currently represent as a distinct enumerated kind.

## Caveats

- GNATprove version, solver versions, and exact message wording are recorded
  above and in `benchmark-results/coap_spark/gnatprove.out` for
  reproducibility.
- This benchmark uses `--timeout=60`, a sixth of coap_spark's own
  `--timeout=360`; all 14 unproved checks are "time and step limit reached,"
  so a wider budget (matching the project's own) would plausibly close some
  or all of them — this run intentionally used the same budget
  `benchmarks/libkeccak/` uses, for cross-benchmark consistency, not the
  widest budget that would produce the cleanest possible number.
- The GNATprove message-text substring matching in `compare.awk` is a
  heuristic against observed wording, not a stable GNATprove API — see
  `benchmarks/sparknacl/README.md`'s caveat for the same point.
- A candidate corpus considered before this one,
  [jgrivera67/HiRTOS](https://github.com/jgrivera67/HiRTOS), was set aside
  after GNATprove hard-errored on a genuine SPARK legality violation in its
  interrupt-handling code, reproducibly from a clean build — not an AdaLang
  defect, but not a usable same-toolchain oracle comparison either. See
  `benchmarks/coap_spark/README.md` for the full account.
