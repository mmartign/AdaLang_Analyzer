# Saatana comparison results — 2026-08-04

## Environment and scope

- HeisenbugLtd/Saatana: `7ba07e735498de39216a30479c3d2cc0817f03ac`
- AdaLang Analyzer: `1.0.0-rc1`, commit `3da60d529d9f957a539b8f505001a7a942964838`
- GNATprove: FSF 16.1.0, Why3 1.8.2+git, CVC5 1.3.2, Z3 4.15.4, Alt-Ergo 2.6.1
- Compiler: Alire `gnat_native` toolchain (this repository's own pin)
- Host: Apple Silicon, macOS 26.5
- Project: `saatana.gpr`, `-U` (all reachable units, both `Main`s), 11 files
  analyzed by AdaLang
- GNATprove ran with `--mode=prove -U --prover=z3,cvc5 --timeout=60 --steps=0
  --report=statistics`, three explicit overrides of Saatana's own `Prove`
  package (see `benchmarks/saatana/README.md`, "Toolchain overrides") needed
  because this toolchain has no CVC4 and Saatana's own per-file switches
  were tuned for CVC4's performance specifically, plus a `--report` level
  the project file doesn't set at all

**Saatana is fully proved at this configuration.** GNATprove's own summary
(`benchmark-results/saatana/gnatprove.out`) reports 404 total checks, 0
unproved, 0 justified — consistent with Saatana's own checked-in
`artifacts/gnatprove.out` (338 checks under real CVC4, GNAT Community 2020),
modulo the additional implicit-termination/initialization checks this
GNATprove version reports by default (see README caveats). That makes
GNATprove a trustworthy oracle here, the same way it is for SPARKNaCl.

## Agreement: matched obligations

Matched by `(file, line, check kind)` — see `benchmarks/saatana/README.md`
and `benchmarks/sparknacl/README.md` for the matching design. **101**
obligations matched 1:1:

| Bucket | Count | Meaning |
| --- | ---: | --- |
| Both safe | 0 | AdaLang `Proved_Safe`, GNATprove proved |
| AdaLang conservative | 101 | AdaLang `Unproved`/`Unsupported`, GNATprove proved |
| Possible AdaLang unsoundness | 0 | AdaLang `Proved_Safe`, GNATprove NOT proved |
| AdaLang false positive | 0 | AdaLang `Definite_Error`, GNATprove proved |
| Both flag a problem | 0 | Both non-safe |

Zero obligations in either headline-risk bucket, consistent with both prior
benchmarks: AdaLang never called something safe that GNATprove could not
prove, and never called something a definite error that GNATprove proved
safe, anywhere in the matched set. Unlike SPARKNaCl (32 "both safe" matches
out of 886), none of Saatana's 56 `Proved_Safe` obligations landed at an
exactly-matching `(file, line, kind)` GNATprove also reports at that
location — with only 101 matched pairs total on a much smaller corpus, this
reads as a sample-size artifact rather than a signal; AdaLang's 56
`Proved_Safe` calls are spread across the corpus and most simply fall in
locations GNATprove's `--mode=prove` output doesn't report at that exact
line (see coverage-only counts below), not in the "both safe" bucket's
complement.

Coverage-only counts (not compared, not errors):

- 775 AdaLang obligations have no GNATprove `--mode=prove` counterpart for
  that kind at their location: `initialization-check` (358, a flow-analysis
  result outside `--mode=prove`'s output, same as SPARKNaCl and CubedOS),
  `range-check` (133), `integer-overflow` (133), `index-check` (80),
  `precondition` (25), `division-by-zero` (25), `assertion` (13),
  `postcondition` (8).
- 66 GNATprove checks (of mapped kinds) have no AdaLang obligation at the
  same location: `range-check` (35), `index-check` (14), `postcondition`
  (10), `integer-overflow` (7) — plausibly `.ads`-only locations or relational
  checks `--verify`'s narrower scalar domain does not attempt, though this
  was not individually confirmed per location (same caveat as SPARKNaCl).
- 97 GNATprove messages have no AdaLang kind mapping at all: flow-analysis
  initialization and data/flow-dependency proofs (58 occurrences), implicit
  `Always_Terminates` proofs (10), length/predicate check proofs (25), and
  loop-unrolling diagnostics (4) — all outside what AdaLang's bounded
  verifier currently attempts, consistent with `POSITIONING.md`.
- 70 locations have a different obligation count on each side (usually
  AdaLang recording 2 for GNATprove's 1, e.g. most `precondition` mismatches
  — the same `FP-033` shape SPARKNaCl's own results already catalogue: a
  call's precondition recorded under two distinct stable IDs) and are left
  unpaired for manual review rather than guessed.

## Conclusion

Saatana adds a third fully-proved SPARK corpus to the independent-oracle
evidence base, from a different author (HeisenbugLtd/Vinzent Saranen) than
either SPARKNaCl or CubedOS, on a single dense cryptographic primitive
(Phelix) rather than a general-purpose library or a message-passing
framework. On the 101 obligations both tools could independently evaluate at
the same location, AdaLang never disagreed with GNATprove's oracle in either
risky direction — zero possible unsoundness, zero false positives — matching
the pattern already established by SPARKNaCl (886 matched pairs) and
CubedOS (7 matched pairs, non-fully-proved). Getting a usable, comparable run
out of this corpus at all required three explicit toolchain overrides (an
unavailable prover named in the project file, a step budget tuned for that
prover specifically, and a report level the project never set) — itself a
useful, honestly-documented reminder that "fully proved" claims from a
project's own CI are tied to the exact toolchain that produced them, not a
toolchain-independent property; a different, newer, otherwise-compatible
GNATprove installation could not reproduce it without those adjustments.

This run's sample size (101 matched pairs) is smaller than SPARKNaCl's and
larger than CubedOS's, reflecting Saatana's own smaller scope (a single
algorithm vs. a full library or framework) — it should be read as
corroborating evidence on top of SPARKNaCl's much larger sample, not an
independent result of comparable statistical weight.
