# SPARK testsuite comparison results — 2026-11-05

Analyzer run of 2026-11-05 with release 1.13.1, on the sources and against
the GNATprove output that the run of 2026-10-02 left for each unit.
GNATprove was not re-run: the testsuite is pinned, and its output was
compared again as saved. The run before this one that is recorded here is
that of 2026-10-02, made with what became release 1.6.2; earlier runs are
in the Git history of this directory, and what each release changed is in
`CHANGELOG.md`. See `README.md` for the per-test-loop design and the
selection criteria behind `MANIFEST.tsv`.

## Environment and scope

- AdaCore/spark2014: branch `fsf-16`, commit
  `42554fc241fcd1fdf08d3a2feccb3f86912acbc0`
- 124 curated testsuite units (90 `clean`, 34 `weak`) — see `MANIFEST.tsv`
- AdaLang Analyzer: release 1.13.1
- GNATprove `--mode=prove`, run 2026-10-02 (FSF 16.1.0, Why3 1.8.2+git, Z3
  4.15.4, CVC5 1.3.2, Alt-Ergo 2.6.1), `--prover=z3,cvc5,altergo
  --steps=16000 --timeout=60 --report=statistics`, output scoped per unit to
  that unit's own source basenames.

"Was" is the run of 2026-10-02.

**Zero possible unsoundness and zero false positives across 124 units
spanning scalar range, overflow, index, division, length, discriminant,
predicate, initialization, loop-invariant and loop-variant obligations.** On the 34
`weak` units no check that GNATprove deliberately leaves at `medium` or
`high` is answered `proved-safe` by AdaLang: of the 36 pairs there, 23 are
flagged by both and the other 13 are checks GNATprove proves. On the lines
of those units that GNATprove flags, every obligation AdaLang proves is of
another kind than the check flagged -- the initialization of an operand,
the termination of the subprogram, the overflow of a subexpression.

### Reading the numbers

- **Matched-pair yield is low by design.** Many units leave AdaLang's
  bounded verifier entirely at `Unproved`/`Unsupported` (contracts,
  quantifiers, relaxed initialization), so "both safe" is only 271 of 650
  matched pairs. The signal this corpus carries is the two **zero**s in
  buckets 3 and 4 across a very wide construct spread, not the matched count
  — the same framing `benchmarks/coap_spark/` uses.
- **Count-mismatch (215) is proportionally higher here** than on the
  single-project corpora: GNATprove splits a check into several VCs at
  distinct columns of one source line, AdaLang records one obligation per
  `(line, kind)`, so `compare.awk` reports the location for manual review
  rather than guessing a pairing.

## What changed since the run of 2026-10-02

The analyzer of that run was what became release 1.6.2. The releases since
have added kinds of obligation (termination, data and flow dependencies,
length checks, the checks inside contracts, predicate checks, dereference
checks, the index checks at the bounds of a target slice, the initialization
checks at calls, the preconditions of calls of generic formal subprograms)
and decided more of the ones there were, which is where the 598 more
obligations, the 223 more pairs and the 230 more "both safe" come from. The
two zeros stand across all of it.

Against release 1.13.0, run the same way on the same saved sources and
output: no obligation is added; 63 range checks of an array value are gone
(61 `Unproved` and 2 `Proved_Safe` by an argument about scalar ranges that
says nothing of an array), an array value being no longer given the range
check of a scalar; and 15 that were `Unproved` are proved, in 6 units: 8
range checks, 3 index checks, 2 assertions, and the initialization and the
preservation of a loop invariant. 9 of them read the elements of an array
of records (`O512-022__DNS_receive_query`, `P518-021__frame_for_max` and
`W306-020__relaxed_init_in_loop_entry` have 3 each), the other 6 an index of
an enumeration type or the bounds an object takes from a slice
(`N214-012__slice` has 4). 9 of them are matched pairs, which go from
AdaLang conservative to both safe, none into the two zero rows; the one
matched pair gone was the range check of an array value.

## An analyzer mistake found by the run of 2026-10-02

`M927-008__bad_constant` first came back as the corpus's only false
positive: for `X : constant Natural := Ident (Integer'Last) + 1;` release
1.6.1 reported both the overflow and the range check as `Definite_Error`,
where GNATprove proves the range check, which is never reached. Fixed as
`FP-100` before this run was recorded; the unit's range check now has no
AdaLang obligation and its overflow is still a "both flag" pair.

## Two analyzer mistakes found by the first run

The 2026-09-06 run surfaced two defects; both are fixed with regression
tests and stay confirmed by this run.

| ID | Unit that found it | Mistake |
| --- | --- | --- |
| `FP-064` | `OB26-006__ctex_array_ret_func` | Indexing into an array *slice* (`Items (1 .. Last) (1)`) was proved safe against the array *type*'s index subtype, ignoring that the slice's own bounds `1 .. Last` are empty when `Last = 0` — a possible unsoundness. Fixed by recording a sliced-prefix index check conservatively as `unproved`. |
| `FP-065` | `W316-007__string_multidim` | `pragma Assert (False)` reported as a definite error on a line the enclosing `if` guard makes unreachable (the `if` line itself always raises `Constraint_Error`). Fixed by keeping the definite-error verdict only where every enclosing branch guard is provably taken. |

`W316-007__string_multidim` is **excluded from `MANIFEST.tsv`**
(`pick_manifest.py`'s `HAND_EXCLUDE`) for a reason independent of the FP-065
fix: GNATprove's own baseline proves the line-13 aggregate range checks that
GNAT rejects at run time, so it is not a sound oracle unit.

See `quality/known_analysis_issues.tsv` (`FP-064`, `FP-065`, `FP-100`).

## Bottom line

A construct-diversity corpus, not another large matched-pair count: 124
independently-authored SPARK regression units, none written with AdaLang's
blind spots in mind, and after the three fixes above AdaLang never calls
safe a check GNATprove cannot prove nor a definite error a check GNATprove
proves.
