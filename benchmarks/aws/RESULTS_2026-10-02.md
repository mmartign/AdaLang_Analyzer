## What changed since 2026-09-30

The three rule lanes are unchanged. `--verify`, compared obligation by
obligation with the 2026-09-30 run (no obligation lost):

- 188 obligations moved to `Proved_Safe`: 81 initialization checks, 69 index
  checks, 31 range checks and 7 overflow checks. They come from what 1.6.1
  added: membership tests and `for` loops over an object's own range narrow
  intervals, array bounds that no declaration fixes are terms the provers
  reason about, and a call to a function in SPARK or in a `Pure` unit, or to
  a predefined attribute, no longer discards what is known, initialization
  included.
- 187 moved from `Proved_Safe` to `Unproved`: 71 overflow checks, 71 index
  checks, 43 range checks and 2 preconditions. They rested on what 1.6.1 no
  longer assumes: the bounds of an array that no declaration fixes
  (`FP-088`), and facts about objects that a call, a loop or an alias can
  change (`FP-090`-`FP-094`). 127 of them name an array attribute directly;
  typical is `Content_Id'First + 1` in `aws-attachments.adb`, for a `String`
  parameter. With no oracle here, nothing says whether any of them was
  wrong.
- 29 precondition obligations are new, for calls to subprograms completed by
  expression functions (`FP-096`).
- The previous run's single `Definite_Error`,
  `templates_parser/src/templates_parser.adb:2112` (range check on
  `Result'First` for `Result : Parameter_Set (1 .. Count)`), is now
  `Proved_Safe`: `Result'First` is 1 whatever `Count` is. It was a false
  positive that this corpus, having no oracle, could not expose. Its
  `Known_Range_Check_Failure` finding is gone with it.
- All ten `Constant_Condition` findings of the previous `--verify` run are
  gone; each was reported from a loop's state before the fixed point
  converged (`FP-095`).

## What this run found

Release 1.6.1 was not run on this corpus before it shipped. Doing so found
two defects, both fixed in the build measured here
(`quality/external_corpus_findings.md`, "Corpus refresh after 1.6.1"):

- **Run time.** The `--verify` lane took 159 s with 1.6.0 and 39 minutes
  with 1.6.1; it takes 69 s now. The report from the build with only the
  run-time fixes is byte-identical to 1.6.1's.
- **`FP-099`.** 1.6.1 reported the read of `C` at
  `src/http2/aws-http2-hpack-huffman.adb:412` as a `Definite_Error`,
  although `C` is the `out` actual of the function called in the enclosing
  condition. It is `Unproved` now, and is the only obligation whose status
  differs from 1.6.1's on this corpus.

## Bottom line

No analyzer failures, and no `Definite_Error` left. No GNATprove oracle for
this corpus (pre-existing legality-error boundary, unchanged).
