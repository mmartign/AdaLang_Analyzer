Spot-checked `aws-net-acceptors.adb:611` directly:

```ada
select
   Acceptor.Semaphore.Seize;
   Shutdown_Internal (Acceptor);
   Acceptor.Semaphore.Release;
   return;
or
   delay 0.0;
end select;
```

A real conditional `select`/`or delay` in the acceptor's shutdown path —
exactly the timing-dependent control flow `No_Select` exists to flag, not
a spurious match. The `No_Requeue` and `No_Abort` findings were similarly
confirmed against their actual source (an entry-call `requeue` in
`aws-net-websocket-registry.adb`'s registration logic, and a real `abort`
statement terminating a stuck SMTP session task in
`aws-smtp-server.adb`).

This closes the gap `benchmarks/README.md` and
`benchmarks/ada_drivers_library/RESULTS_2026-08-05.md` both flagged:
`ada_drivers_library`'s tasking is entirely Ravenscar-restricted (no
`task`/`select`/`requeue` to exercise), so those three checks' true-positive

## Newly found, not yet fixed: a `--verify` initialization false positive

All 4 `Definite_Error` outcomes are the same shape, in
`aws-extended/aws-server-push.adb`'s protected bodies:

```ada
procedure Shutdown_If_Empty (Open : out Boolean) is
   use type Ada.Containers.Count_Type;
begin
   if Container.Length = 0 then
      Object.Open := False;
   end if;
   Shutdown_If_Empty.Open := Object.Open;   -- flagged: "uninitialized on
end Shutdown_If_Empty;                      -- every incoming path"

procedure Info
  (Size        : out Natural;
   Max_Size    : out Natural;
   Max_Size_DT : out Calendar.Time;
   Counter     : out Wait_Counter_Type) is
begin
   Info.Size        := Waiter_Information.Size - 1;   -- Size, Max_Size,
   Info.Max_Size    := Waiter_Information.Max_Size - 1; -- and Counter all
   Info.Max_Size_DT := Waiter_Information.Max_Size_DT;  -- flagged the
   Info.Counter     := Waiter_Information.Counter;      -- same way
end Info;
```

Both write their `out` formals unconditionally, qualified by the enclosing
subprogram's own name (`Shutdown_If_Empty.Open`, `Info.Size`, ...) — Ada's
ordinary way to disambiguate a formal from a same-named component on the
enclosing protected object (here, both the protected type and one of its
components are named `Waiter_Information`/`Open`). This exact shape was
already found and fixed once, in `Adalang_Analyzer.SPARK_Readiness.
Same_Parameter` (`FP-011`, found on an earlier AWS run, same file,
`Info`/`Shutdown_If_Empty` even named as examples) — but that fix lives in
the `--recommended`/`Uninitialized_Output` code path only.
`--verify`'s own, separate initialization-tracking engine
(`Adalang_Analyzer.Flow_Interp`) apparently never received the equivalent
fix, so the identical shape still produces a `Definite_Error` there. Not
fixed in this pass — flagged here rather than left for the next real-corpus
run to rediscover; tracking as a candidate for a future `FP-0NN` entry in
`quality/known_analysis_issues.tsv`.
