# AWS comparison benchmark

This benchmark compares AdaLang Analyzer's ordinary-Ada and bounded-verifier
coverage with GNATprove's SPARK analysis boundary on a pinned Ada Web Server
(AWS) revision. It is a workflow comparison, not an equivalence claim: the
tools answer different questions and only a shared, successfully analyzed
obligation can support a direct proof-result comparison.

## Pinned sources

- AdaCore/aws: `02cbd01c2f96c288440415a46bf865616c0ee0f8`
- templates_parser submodule: `7c59ed4f1ee371c7d3f420b890e287b72c2473f4`

Clone and configure the corpus from the AdaLang Analyzer repository root:

```sh
git clone --recurse-submodules https://github.com/AdaCore/aws.git \
  /private/tmp/adalang-aws-benchmark
git -C /private/tmp/adalang-aws-benchmark checkout \
  02cbd01c2f96c288440415a46bf865616c0ee0f8
git -C /private/tmp/adalang-aws-benchmark/templates_parser checkout \
  7c59ed4f1ee371c7d3f420b890e287b72c2473f4
alr exec -- make -C /private/tmp/adalang-aws-benchmark setup build \
  ENABLE_SHARED=false XMLADA=true LAL=false SOCKET=std
```

Run the benchmark:

```sh
AWS_ROOT=/private/tmp/adalang-aws-benchmark sh benchmarks/aws/run.sh
```

On a non-Darwin host, set `AWS_PRJ_TARGET` to the value generated by AWS's
setup (for example `UNIX`). Set `GNATPROVE_DIAGNOSTIC=true` to additionally run
the derived, single-body-excluded flow experiment described below.

`run.sh` verifies both revisions, derives the configured target directory from
the active Alire compiler, and runs:

- AdaLang `--recommended`, `--spark`, `--verify`, and `--automotive` against
  `src/src.gpr`;
- GNATprove `--mode=flow` and `--mode=prove --level=0` against the same project;
- machine-readable JSON summaries and POSIX timing files.

The `--automotive` lane exists to exercise the concurrency-prohibition
checks (`No_Select`, `No_Requeue`, `No_Abort`, `No_Rendezvous`,
`No_Asynchronous_Transfer`) against real full-tasking code: unlike the
Ravenscar-restricted embedded corpora here (`ada_drivers_library`), AWS's
own core server code (`aws-server.adb`, `aws-net-acceptors.adb`,
`aws-session.adb`, `aws-server-push.adb`, and others) genuinely uses
`select`, `requeue`, and `abort`, so this is the corpus that confirms those
checks' true-positive behavior on unmodified, independently authored code.

The AWS build configuration is static, debug, standard sockets, XML/Ada
enabled, Libadalang-based AWS tools disabled, and LDAP disabled. The root
`aws.gpr` is an aggregate project with no direct source units, so both tools
are intentionally given its concrete `src/src.gpr` library project.

Exit status 1 is accepted for AdaLang because it means findings were emitted.
GNATprove statuses are captured rather than treated as runner failures because
SPARK rejection is itself a measured outcome on ordinary Ada.

The diagnostic experiment in the recorded results uses a derived project that
excludes only `aws-client-http_utils.adb`, the body that prevents unmodified
GNATprove runs from completing project-wide preprocessing. That experiment is
clearly separated from the primary, unmodified-source lanes and is opt-in.
