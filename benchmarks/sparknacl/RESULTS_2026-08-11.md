## The one real delta: 41 fewer total obligations, all outside the matched set

| | 2026-08-04 | 2026-08-11 | Δ |
| --- | ---: | ---: | ---: |
| Total proof obligations | 9,531 | 9,490 | **−41** |
| `Proved_Safe` | 3,457 | 3,435 | **−22** |
| `Unproved` | 4,531 | 4,523 | **−8** |
| `Unsupported` | 1,543 | 1,532 | **−11** |
| AdaLang-only (no GNATprove counterpart) | 5,297 | 5,273 | **−24** |

Every one of the 886 matched pairs and both risk-bucket counts (possible
unsoundness, false positive) are bit-identical to baseline, so this is not
a change in what AdaLang concludes about any obligation GNATprove also has
an opinion on — it's a change in how many obligations get registered at
all, concentrated in the `initialization-check` category within the
unmatched pool (down from the 2,424 baseline documents implicitly via its
own 5,297 AdaLang-only total to 2,400 here).

This is very unlikely to be `FP-047` (the `/`/`mod`/`rem` SMT work): that
change can only add new `Proved_Safe`/`Definite_Error` verdicts to
already-registered obligations, not remove obligations from registration,
and `initialization-check` obligations don't route through `VC_Prover` at
all. More plausibly, this is the same class of interim-fix drift the
`aws` benchmark's own 2026-08-11 re-run independently traced line-for-line
to `FP-046` (an own-name-qualified out-parameter write previously misread
as a read, fixed in this repository's `flow_interp.adb` between the
2026-08-04 baseline and now) — SPARKNaCl's initialization-heavy proof
obligation shape is exactly what that fix touches. Unlike `aws`, this
wasn't independently re-confirmed line-by-line here (no archived
2026-08-04 raw JSON survives to diff against, `benchmark-results/` being
gitignored), so treat the `FP-046` attribution as plausible, not
confirmed, for this specific corpus.

## Bottom line

No change to the numbers that matter most: zero possible unsoundness, zero
false positives, 886/32/850/4 bucket split all identical to the 2026-08-04
baseline. `FP-047`'s new `/`/`mod`/`rem` SMT support did not move
SPARKNaCl's "both safe" rate (still 32/886 ≈ 4%) — consistent with
SPARKNaCl's own arithmetic being mostly fixed-width bitwise/additive
operations rather than division/modulo, the shape `FP-047` targets. The
41-obligation drop outside the matched set is plausibly `FP-046`'s effect
on initialization-check registration, the same interim fix `aws`'s
2026-08-11 re-run confirmed exactly, not a regression from this session's
own change.
