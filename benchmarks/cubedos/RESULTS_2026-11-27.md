# CubedOS comparison results — 2026-11-27

Analyzer run of 2026-11-27 with release 1.17.6, replacing the 2026-11-26 run
of release 1.17.5. GNATprove was not re-run: the corpus is pinned, and its
output of 2026-10-02 was compared again as saved. Earlier runs are in the
Git history of this directory, and what each release changed is in
`CHANGELOG.md`.

A pair is a `(file, line, kind)` at which each tool has exactly one
obligation. Of the ten pairs six are range checks and four are preconditions;
nine are left at `medium` by GNATprove and `Unproved` by AdaLang. Five more
locations are not paired because AdaLang has two obligations of a kind on a
line where GNATprove has one message.

The tenth pair is the one `Definite_Error`, a precondition, and the error is
real: `Handle_Add_Request`, whose precondition is `Is_Add_Request (Message)`,
calls `Add_Request_Decode`, whose precondition is `Is_Set_Request (Message)`;
the two cannot both hold (`Message_ID` is the position of `Add_Request` in one
and of `Set_Request` in the other). GNATprove reports the call at `high`:
"precondition might fail", with `Message_ID => 3`.

## What changed since 1.17.5

Every obligation has the verdict it had with 1.17.5.

1 `Missing_Global_Contract` finding is new in `--verify`: a call to a
subprogram whose Global aspect names a state abstraction touches that state
(`Ada.Text_IO`'s `File_System`, `Interfaces.C.Strings`' `C_Memory`), so a
subprogram that reaches state only through such calls has global state for
which GNATprove would generate a Global (FP-181).

15 `Missing_Global_Contract` findings are gone from `--verify`: a subprogram
that reads only constants whose value depends on no variable accesses no
global state (FP-181).

11 `Global_Contract_Mismatch` findings are gone from `--verify`: a read or
write of a constituent of a state abstraction is allowed as the Global aspect
allows the state, a body is held to its `Refined_Global`, a constant whose
value depends on no variable is no global, and an `Output` global may be read
once the body has given it a value first (FP-181, FP-189).

2 `Dead_Store` findings are gone from `--verify`: the value a call stores at
the end of a loop pass that the next pass reads is not dead (FP-186).

## Bottom line

Zero possible unsoundness, zero false positives, and no file-level
failures.
