# CubedOS comparison results — 2026-08-04

## Environment and scope

- cubesatlab/cubedos: `c402301000a5a92237e0f7ab106186a48273cf24`
- AdaLang Analyzer: `1.0.0-rc1`, commit `ddb208cacd2935f3b3307eb6897d904e5cc2f7a2`
- GNATprove: FSF 16.1.0, Why3 1.8.2+git, CVC5 1.3.2, Z3 4.15.4, Alt-Ergo 2.6.1
- Compiler: Alire `gnat_native` toolchain (this repository's own pin)
- AUnit: Alire `aunit` 26.0.0, resolved via a throwaway crate (see
  `benchmarks/cubedos/README.md`)
- Host: Apple Silicon, macOS 26.5
- Project: `src/cubedos.gpr`, unmodified, 49 files analyzed by both tools
  (the `check/` AUnit test suite and `modules`/`library` core, excluding
  `samples/`, `bench/`, `mercury/`, `scriptbuilder/`, which have their own,
  separate project files not analyzed here)
- GNATprove ran with `--mode=prove --level=4 --prover=z3,cvc5,altergo
  --timeout=60`, explicitly chosen to match SPARKNaCl's own tuned
  configuration; `cubedos.gpr` itself declares an empty `package Prove`

**Unlike SPARKNaCl, CubedOS is not a fully-proved corpus.** GNATprove's own
`--mode=prove` run on unmodified `cubedos.gpr` reports real `high`/`medium`
findings: tasking data races on `Message_Manager.Mailboxes` shared across
`log_server`/`time_server`/`interpreter`/`transport_udp` message loops, a
`Global` aspect omission (SPARK RM 6.1.4(15)), four `out` parameters not
initialized on every path, and a number of `medium` range/precondition
checks where "provers reached time limit before completing the proof". None
of this is a defect in AdaLang; it means GNATprove's own verdict here is not
a trustworthy "ground truth" oracle the way it is on SPARKNaCl, so this
benchmark cannot ask the same "does AdaLang ever disagree with a fully-proved
oracle" question. Its value is a second, structurally different real SPARK
corpus to exercise `--verify` against.

## New analyzer limitation surfaced: FP-040 (open)

`--verify`'s proof-obligation finalization pass hit Libadalang's own
`Property_Error` ("undetermined CallExpr kind", occasionally "dereferencing
a null access") on **21 of the 49 analyzed files**, falling back
conservatively per file (the run completes; each occurrence is reported as a
"recoverable analysis failure" warning on stderr, not a crash). `gnatls` was
present and resolvable throughout this run, ruling out the already-documented
`FP-029` (a different error signature triggered specifically by a missing
`gnatls`). Full detail, including the affected file list, is recorded as
`FP-040` in `quality/known_analysis_issues.tsv`; it has not been root-caused
yet.

The practical effect on this run: `--verify` reports only 44 proof
obligations project-wide (2 `Proved_Safe`, 0 `Definite_Error`, 9 `Unproved`,
33 `Unsupported`) — implausibly low for 49 files, and dominated by this
fallback rather than by genuine bounded-verification scope limits. The
comparison below should be read as "what limited signal is available at this
revision," not as a measurement of `--verify`'s real coverage on CubedOS.

## Agreement: matched obligations

Matched by `(file, line, check kind)` — see `benchmarks/cubedos/README.md`
and `benchmarks/sparknacl/README.md` for the matching design. Only **2**
obligations matched 1:1, both in bucket 5 ("both flag a problem" — AdaLang
`Unsupported`, GNATprove not-proved on a range check), a direct consequence
of FP-040: 42 of AdaLang's 44 obligations have no GNATprove-mapped
counterpart at their location, almost entirely because FP-040's fallback
suppressed obligation registration in the very files where GNATprove found
something to compare against.

| Bucket | Count | Meaning |
| --- | ---: | --- |
| Both safe | 0 | AdaLang `Proved_Safe`, GNATprove proved |
| AdaLang conservative | 0 | AdaLang `Unproved`/`Unsupported`, GNATprove proved |
| Possible AdaLang unsoundness | 0 | AdaLang `Proved_Safe`, GNATprove NOT proved |
| AdaLang false positive | 0 | AdaLang `Definite_Error`, GNATprove proved |
| Both flag a problem | 2 | Both non-safe |

As with SPARKNaCl, zero obligations fell in either headline-risk bucket
(possible unsoundness, false positive) — but with only 2 matched pairs total
at this revision, that is a much weaker signal than SPARKNaCl's 886-pair
comparison and should not be read as evidence of anything beyond "no
disagreement was observed in the small sample that survived FP-040."

Coverage-only counts (not compared, not errors):

- 42 AdaLang obligations have no GNATprove `--mode=prove` counterpart for
  that kind at their location: `range-check` (29), `initialization-check`
  (7, a flow-analysis result outside `--mode=prove`'s output, same as
  SPARKNaCl), `integer-overflow` (4), `assertion` (2).
- 17 GNATprove checks (of mapped kinds) have no AdaLang obligation at the
  same location: `range-check` (12), `precondition` (4), `integer-overflow`
  (1) — plausibly FP-040 suppressing the corresponding AdaLang obligation in
  the same file, though this was not individually confirmed per location.
- 45 GNATprove messages have no AdaLang kind mapping at all: tasking data
  races and the `Global`-aspect omission (14, expected — concurrency
  analysis is explicitly out of scope per `POSITIONING.md`), out-parameter
  initialization proofs (6), loop-unrolling/inlining diagnostics (16), and
  call-context analysis notes (9).

## Conclusion

This run's main finding is `FP-040`, not a proof-agreement number: CubedOS's
message-passing/XDR-marshalling code shape triggered a previously-unseen
Libadalang `Property_Error` on 21 of 49 files, undercounting `--verify`'s
proof obligations enough to make the per-obligation comparison
uninformative at this revision. The zero-disagreement result on the 2 pairs
that did match is consistent with SPARKNaCl's finding but far too small a
sample to add confidence beyond it. Re-running this benchmark after FP-040
is root-caused (or at minimum after its trigger is narrowed to a specific
construct) is the natural next step; until then, this corpus's chief value
has already been delivered — a real, previously-undiscovered analyzer
limitation, caught by external-corpus validation exactly the way
`quality/external_corpus_findings.md` intends.
