# Libkeccak comparison results — 2026-08-07

## Environment and scope

- damaki/libkeccak: `4b7174fccbf5461998b18395aaeecc68bb25798d`
- AdaLang Analyzer: `1.0.0-rc1`, commit `681844c098ffb2d846b61a0253753c5c85e7e488`
- GNATprove: FSF 16.1.0, Why3 1.8.2+git, CVC5 1.3.2, Z3 4.15.4, Alt-Ergo 2.6.1
- Compiler: Alire `gnat_native` toolchain (this repository's own pin)
- Host: Apple Silicon, macOS 26.5.2
- Project: `libkeccak.gpr -XLIBKECCAK_ARCH=generic -XLIBKECCAK_SIMD=none`, 100
  source files under `src/common/` and `src/generic/`, analyzed by both tools
- GNATprove ran with `-P libkeccak.gpr -XLIBKECCAK_ARCH=generic
  -XLIBKECCAK_SIMD=none --mode=prove -f -q --output=oneline
  --prover=z3,cvc5,altergo`, one override of libkeccak's own `Prove` package
  (`--prover=cvc4,z3,altergo` → `--prover=z3,cvc5,altergo`, since this
  toolchain ships CVC5, not CVC4 — see `benchmarks/libkeccak/README.md`,
  "Toolchain override"); the project's own `--steps=16000 --timeout=60`
  budget was used unmodified and needed no further widening

**Libkeccak is fully proved at this configuration.** GNATprove's own summary
(`benchmark-results/libkeccak/gnatprove.out`) reports 21,077 total checks,
0 unproved, 78 justified (0%) — the justified entries are exactly the
initialization checks the library's own README documents as manually
reviewed and suppressed with `pragma Annotate` because GNATprove's flow
analysis cannot automatically verify them through the library's
initialization loops. That makes GNATprove a trustworthy oracle here, the
same way it is for SPARKNaCl and Saatana.

## Agreement: matched obligations

Matched by `(file, line, check kind)` — see `benchmarks/libkeccak/README.md`
and `benchmarks/sparknacl/README.md` for the matching design. **212**
obligations matched 1:1:

| Bucket | Count | Meaning |
| --- | ---: | --- |
| Both safe | 50 | AdaLang `Proved_Safe`, GNATprove proved |
| AdaLang conservative | 162 | AdaLang `Unproved`/`Unsupported`, GNATprove proved |
| **Possible AdaLang unsoundness** | **0** | AdaLang `Proved_Safe`, GNATprove NOT proved |
| **AdaLang false positive** | **0** | AdaLang `Definite_Error`, GNATprove proved |
| Both flag a problem | 0 | Both non-safe |

Zero obligations in either headline-risk bucket, consistent with SPARKNaCl
and Saatana: AdaLang never called something safe that GNATprove could not
prove, and never called something a definite error that GNATprove proved
safe, anywhere in the matched set.

### Why the matched-pair count is small relative to the obligation totals

Unlike SPARKNaCl (886 matched pairs out of 9,531 AdaLang obligations) and
Saatana (101 out of 1,363), libkeccak's matched-pair count (212 out of
11,202) is small in *proportion*, not because matching failed but because
of **1,390 count-mismatch keys** — the largest such bucket of any of this
repository's benchmarks. Libkeccak instantiates its generic permutation,
sponge, and padding cores repeatedly, once per supported state size and
round count (Keccak-25 through Keccak-1600, Gimli, Ascon, each with several
round-count variants). GNATprove reports one `info`/check message *per
instantiation site*, so a single generic source line can produce a dozen or
more GNATprove messages (observed up to 16, e.g.
`keccak-generic_sponge.adb:374` range-check: `adalang=1 gnatprove=16`) while
AdaLang, which analyzes the generic source once, reports one obligation at
that line. `compare.awk`'s matching design deliberately does not guess which
instantiation an AdaLang obligation corresponds to in this situation —
consistent with its existing "don't auto-pair on a count mismatch" policy —
so these locations fall into the count-mismatch bucket for manual review
rather than being silently force-matched or dropped. This is a property of
the corpus's coding style (heavy generic reuse), not a matching defect
specific to this benchmark; SPARKNaCl and Saatana simply have much less
generic instantiation, so the same design choice was invisible there.

## Coverage-only counts

- **6,090** AdaLang obligations have no GNATprove `--mode=prove` counterpart
  for that kind at any matched location — dominated by `initialization-check`
  (3,085), the same category that dominates SPARKNaCl's coverage-only count,
  for the same reason: GNATprove tracks initialization primarily as a flow
  fact rather than a per-obligation "proved" check message in
  `--output=oneline`.
- **613** GNATprove-only obligations (a mapped kind, but no AdaLang
  obligation recorded at that exact location) — `range-check` (330) and
  `precondition` (118) dominate; largely a byproduct of the same
  instantiation-multiplication effect described above interacting with the
  matching design's per-location keying.
- **8,633** GNATprove messages have no AdaLang kind mapping at all —
  overwhelmingly flow facts (`initialization of "<var>" proved`,
  `implicit aspect Always_Terminates on "<entity>" has been proved`,
  parameter-value-after-call facts) that `--verify`'s obligation model does
  not currently represent as a distinct enumerated kind.

## Caveats

- Prover/solver versions and exact message wording are recorded above and
  in `benchmark-results/libkeccak/gnatprove.out` for reproducibility.
- Libkeccak's proofs cover run-time-error freedom only (SPARK silver level),
  not functional correctness; this comparison is scoped to the same
  run-time-error obligation category `--verify` targets, so that
  distinction does not affect the soundness/precision numbers above.
- The GNATprove message-text substring matching in `compare.awk` is a
  heuristic against observed wording, not a stable GNATprove API — see
  `benchmarks/sparknacl/README.md`'s caveat for the same point.
- A candidate corpus considered before this one,
  [Componolit/libsparkcrypto](https://github.com/Componolit/libsparkcrypto),
  was set aside after hitting a genuine `gnat2why` internal crash
  (`Program_Error gnat2why-unchecked_conversion.adb:965`) on this
  benchmark suite's GNATprove version, blocking most of its hash-related
  units — not an AdaLang defect, but not a usable same-toolchain oracle
  comparison either.
