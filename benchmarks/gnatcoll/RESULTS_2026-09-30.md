## What changed since 2026-08-29

All of the `--verify` change is `FP-084`. This corpus has the highest share
of subprograms whose fixed-point run stops on a Libadalang property error
(`undetermined CallExpr kind`, null-access dereferences inside
Libadalang). The previous build finalized those runs from a half-filled
state; it now records them as `Unsupported`:

- all 1,072 `Unreachable` results were artifacts of this;
- 107 `Proved_Safe` and 141 `Unproved` results came from the same
  half-finished runs (for example the four overloaded `Distance`
  functions in `gnatcoll-geometry.adb`);
- 145 obligations the previous build never enumerated there are now
  recorded as `Unsupported`.

The lower `Proved_Safe` count is therefore a withdrawal of results that
never rested on a completed analysis, not a loss of proof capability.
Compared obligation by obligation with the 1.5.3 build on the same
checkout, no obligation is lost, and both builds stop on exactly the same
set of Libadalang failures.

Rule-finding changes below come from releases 1.5.1–1.5.3, not from this
change: re-running the same checkout with the 1.5.3 build gives identical
finding counts in every rule lane. The previous results predate those
releases.

## Bottom line

No analyzer failures. No GNATprove oracle for this corpus (pre-existing
flow-analysis boundary, unchanged: `gnatcoll-strings.ads:31`, `function
associated to aspect Iterable with dependency on globals is not allowed in
SPARK`). Every `Proved_Safe` and `Unreachable` result now rests on a
completed analysis.
